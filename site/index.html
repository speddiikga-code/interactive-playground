00The naming, corrected

Three terms circulate loosely, and getting them straight changes the architecture — not just the vocabulary.

Real

ultracode

A Claude Code feature — both a keyword and an effort level, combining xhigh reasoning with automatic multi-agent workflow orchestration.

Not a product

GPT Ultra

No OpenAI model ships under this name. The current frontier coding models are GPT‑6 Astra (gpt-6-astra, released 3 Sep 2026) and the GPT‑5.6 family — Sol, Terra, Luna.

Doesn't exist

OpenAI ultracode

Codex has no workflow-orchestration mode. Its nearest knob is reasoning_effort = "xhigh" — a deeper single agent loop, which is a different thing entirely.

So "run ultracode across both vendors" is not achievable as stated. A wrapper that pretends otherwise gives you the lowest common denominator — worse than either harness alone. What is achievable is below.

01The four-layer thesis

Claude Code and Codex are different harnesses: different loop, tool names, permission model, context strategy. Don't abstract the harness. Unify the four layers around it — each one a single file.

L1 Instructions AGENTS.md — both read it natively
L2 Tools .mcp.json — both speak MCP
L3 Verification preflight.sh — neither may skip it
L4 Routing agent-route.mjs — picks the harness

↓   feeds both   ↓

Claude Code

Dynamic workflows, subagent fan-out, ultracode.

OpenAI Codex

gpt-6-astra, long-horizon runs, reasoning_effort.

Swap a harness out and three of the four layers are untouched. That is the whole integration — and the reason it survives the next model release.

02Route your task

The most expensive habit in agentic coding is running everything at maximum effort. Describe a real task and see where it should go. This runs the same classification the repo's agent-route.mjs uses.

03The ladder

Almost every costly mistake is using a rung higher than the task needs. Work up, never down.

RungWhat it isUse when
1AutocompleteYou know exactly what to type
2Single turnThe task fits in one reply
3Agent loopMulti-step; needs to read and run things
4Orchestration — a script spawns many agentsThe same step repeats across many items

Rungs 1–3 are what both CLIs do out of the box. Rung 4 is what ultracode adds, and only Claude Code has it.

04What ultracode actually does

It moves the plan out of the context window and into a script.

Normally Claude decides turn by turn what to do next, and every intermediate result lands in its context. A workflow is JavaScript that holds the loop, the branching, and the intermediate results itself — so the context holds only the final answer. That is what lets one run coordinate hundreds of agents instead of a handful.

export const meta = { name: 'audit-routes', description: 'Auth check sweep' }

const found = await agent('List every .ts file under src/routes/.', {
  schema: { type: 'object', required: ['files'],
            properties: { files: { type: 'array', items: { type: 'string' } } } },
})

const audits = await pipeline(found.files, file =>
  agent(`Audit ${file} for missing authentication checks.`, { label: file }),
)

return audits.filter(Boolean)   // agent() resolves null when stopped

The second, less obvious benefit: because the plan is code, it can encode a quality pattern. Independent agents can adversarially refute each other's findings before anything is reported — structurally more trustworthy than one confident pass.

Three ways in

ultracode: <task>            # one task, this once
/effort ultracode            # this session, every substantive task
claude --effort ultracode    # start the session that way
Security property, not a limitation

The keyword fires only from input you type yourself — not claude -p, not a scheduled task, not a webhook or PR comment (since v2.1.210).

Before that, it fired from all of them: a PR comment containing the word could spawn dozens of agents on your account. Leave that boundary alone.

05Hard edges

These are not style preferences. Violate them and the run fails.

ConstraintConsequence
import() is rejectedThe script fails before the run starts
No filesystem or shell from the scriptAgents do that work; the script only coordinates
Date.now(), Math.random(), bare new Date() throwSo a resumed run replays identically — pass time via args
4,096 itemsMax per parallel() / pipeline(); longer lists error
1,000 agentsPer run — prevents runaway loops
16 concurrentDefault; tune via CLAUDE_CODE_WORKFLOW_MAX_CONCURRENT_AGENTS
No mid-run user inputFor sign-off between stages, run each stage as its own workflow
Found the hard way

node --check cannot validate a workflow script. These files mix ESM export with top-level await and top-level return — valid in the workflow runtime, but in neither of Node's module modes.

Node's detection tries CommonJS, fails, tries ESM, fails, and then exits 0. A file with a genuine syntax error passes clean. Verified on Node v22.22.2. Strip the meta export and compile the body as an async function body instead.

The long-context premium

A large context window is not free just because your input fits in it. On gpt-6-astra, past 272K tokens you pay 2× input and 1.5× output.

So context hygiene is a cost lever, not only a quality one — trimming 300K to 250K can more than halve the input bill.

Free wins, before you touch effort

  • Prompt caching. A prefix match — any byte change invalidates everything after it. Stable content first, volatile last. If cache_read_input_tokens is zero across repeated requests, something is silently invalidating.
  • Workflow cache TTL. Workflow agents get 5 minutes by default, separate from the main session. On a wide fan-out set subagentPromptCacheTtl: "1h".
  • Batch where latency doesn't matter — roughly 50% off on both sides.

Judge cost per completed task, not per request. A cheaper request that needs three more rounds is not cheaper.

0730-minute setup

  1. Install both CLIs

    Version floors matter: ultracode needs Claude Code v2.1.203+, and gpt-6-astra needs Codex v0.153.1+.

    npm install -g @anthropic-ai/claude-code
npm install -g @openai/codex

  2. Write the contract

    Every behavioral rule goes in AGENTS.md. CLAUDE.md is a pointer to it — a second copy is a second thing to forget to update. Rules must be specific and checkable: "exit code 0" is observable, "good code" isn't.

  3. Make the gate real

    The highest-leverage file. Both agents run it before pushing, and CI runs the identical script — so an agent cannot be "green locally, red in CI." One definition of green.

    ./scripts/preflight.sh

  4. Calibrate on one real task

    Give the same task to both and compare. Then ask both to restate the contract — if the summaries differ materially, your AGENTS.md is ambiguous. It's the cheapest eval you'll ever write.

    claude "Summarize the non-negotiables in AGENTS.md."
codex  "Summarize the non-negotiables in AGENTS.md."

08What will bite you

  1. The keyword only fires from human-typed input. Not -p, not scheduled tasks, not webhooks or PR comments. Deliberate — otherwise a comment could spend $400 of your budget.
  2. A failed agent reruns everything after it. If a script starts A, B, C, D and B fails, relaunching returns A from cache and re-runs B, C, and D. Order expensive stages after cheap ones.
  3. Workflow agents get a 5-minute cache TTL, separate from your session. On a big fan-out you re-pay for the same prefix over and over.
  4. temperature and top_p are rejected by current frontier reasoning models on both sides. Old scripts carrying them will 400. So will reasoning_effort = "none".
  5. The Large workflow warning is advisory and doesn't pause anything — and sessions with ultracode on don't show it at all, because turning it on already opts you into large runs.
  6. In auto permission mode with ultracode on, workflows start without asking. Fine on a scratch repo; a poor fit for one holding production credentials.

Model IDs, pricing, and runtime limits were verified against current documentation in September 2026 and will drift. The ultracode mechanics reflect Claude Code v2.1.x; check the version floors before relying on any one flag.

Anthropic pricing is first-party. OpenAI pricing is from a third-party reference — confirm it before budgeting.
